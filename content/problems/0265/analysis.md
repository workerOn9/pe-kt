# 265 — Binary Circles（二进制圆圈）

## 建模

一条满足要求的圆周二进制串（$2^N$ 个位、所有 $N$ 位顺时针窗口互不相同）就是**二元 $N$ 阶 de Bruijn 序列**。把窗口当作状态、把「在哪一个 $N$ 位串上」当作边，可以把它变成图论问题。

构造 **de Bruijn 图 $B(2,N)$**：

- 顶点：全部 $2^{N-1}$ 个 $(N-1)$ 位串；
- 边：全部 $2^N$ 个 $N$ 位串 $b_1b_2\cdots b_N$，从顶点 $b_1\cdots b_{N-1}$ 指向 $b_2\cdots b_N$。

每个顶点出度、入度都等于 $2$。一条圆排列的 $2^N$ 个窗口恰好是一条「每条边恰走一次并回到起点」的闭合走法，即**欧拉回路**；反之任一欧拉回路按边序读出窗口，就是唯一的圆排列。忽略旋转的不同圆排列个数是熟知的

$$
\#\{\text{de Bruijn cycles}\}=2^{\,2^{N-1}-N},
$$

$N=5$ 时等于 $2^{11}=2048$。

题目的编码口径是「从全零窗口开始拼接」。全零边 $0^N$ 在一条回路里恰好出现一次，所以每个圆排列恰好对应一条**以 $0^N$ 为首边、从顶点 $0^{N-1}$ 出发**的欧拉回路，两者一一对应：

$$
S(N)=\sum_{\text{以 } 0^N \text{ 为首边的欧拉回路}} \overline{b_0b_1\cdots b_{2^N-1}}_2 .
$$

DFS 时从 $0^{N-1}$ 出发、先走边 $0^N$，之后每步在图上选一条未用过的出边（$b\in\{0,1\}$），用满 $2^N$ 条边且回到起点即得一条回路。新边串的第 $i$ 条边贡献位串下标 $i+N-1$ 处的比特；下标达到 $2^N$ 之后的「回绕比特」只有在全为 $0$（等价于终点回到 $0^{N-1}$）时才可能被接受，因此不影响拼接：DFS 天然只数规范化后的编码，无需事后去重或旋转。

## 独立复核（方法 B）

方法 B 换一个完全不同的入口：**不固定首边**，从顶点 $0^{N-1}$ 出发枚举全部欧拉回路（共 $2\times2048=4096$ 条 —— 每条圆排列在回路里两次经过 $0^{N-1}$，故各被数两次）。对每条回路，先定位全零边，再在**它的位置重新起读**拼接出编码，放进集合去重。它完全不依赖「首边即 $0^N$ 会自动规范化」这一论证，独立地把「忽略旋转」的口径再实现了一遍：若方法 A 的规范化写错，方法 B 会给出 4096 个互不相同的编码而不是 2048 个。

两种实现在 $N=3,4,5$ 上的编码集合、个数、和完全一致（$N=5$：2048 个，和 $209110240768$）。

## 直接暴力对照

`brute-force.kt` 完全不使用图论结构，按定义硬枚举：候选是全部前 $N$ 位为 $0$ 的 $2^{2^N-N}$ 个位串，逐个检查全部 $2^N$ 个循环窗口是否两两不同（第 $j$ 个窗口 = 位串在 $2^N$ 位宽度内循环左移 $j$ 位后的最高 $N$ 位，含回绕窗口）。前 $N$ 位为 $0$ 保证候选以唯一的全零窗口开头，因此每个圆排列恰好被数一次。

- $N=3$：32 个候选 → 编码 $[23,29]$，和 $52$，与题面逐值一致；
- $N=4$：4096 个候选 → $16$ 个合法，和 $51504$，与方法 A、B 一致；
- $N=5$：$134\,217\,728$ 个候选 → $2048$ 个合法，和 $209110240768$，与方法 A、B 一致。

（$N=4$ 的 $16$ 也与公式 $2^{2^{3}-4}=16$ 吻合。）

## 旁证

1. **题面锚点**：$N=3$ 时方法 A、方法 B、直接暴力三种实现都给出编码 $23,29$ 与 $S(3)=52$，逐值复现题面。
2. **结构性对照**：实得合法圆排列数 $2048=2^{2^{5-1}-5}=2^{11}$，与 de Bruijn 序列计数的闭式吻合；$N=4$ 的 $16=2^{2^{3}-4}$ 同理。
3. **公开答案表**：Project Euler 265 的公开解答汇总给出 $S(5)=209110240768$（仅作旁证；`meta.answer` 取自本机实跑输出）。

## 答案

实跑输出（方法 A、方法 B、直接暴力一致）：

$$
\boxed{209110240768}
$$

## 复杂度对比

| 方法 | 规模 | 本机实测（JIT 预热后 3 轮最优） |
|:--|:--|:--|
| 直接暴力 $N=3$ | $32$ 个候选 $\times\le 8$ 个窗口检查 | $<0.1$ ms |
| 直接暴力 $N=4$ | $4096$ 个候选 $\times\le 16$ 个窗口检查 | $0.1$ ms |
| 直接暴力 $N=5$（`brute-force.kt`，meta 的 `bruteForceBaselineMs`） | $134\,217\,728$ 个候选 $\times\le 32$ 个窗口检查 | $683.4$ ms |
| 方法 A $N=5$（`solution.kt` 主路径，meta 的 `optimizedBaselineMs`） | $92\,636$ 个 「边互异的部分回路」搜索状态 | $0.5$ ms |
| 方法 B $N=5$（独立复核） | $198\,882$ 个搜索状态 + $4096$ 次规范化后 $2048$ 条集合去重 | $3.0$ ms |

内存：两种方法都只用 $O(2^N)$（`used` 标记与回路序列），无额外结构。

## 关键教训

- **「忽略旋转」在建模阶段就能消掉，不必事后去重。** 全零边在回路里唯一出现，把它钉成首边就把旋转自由度的整条轨道一次消除；方法 A 因此比方法 B 快 $6$ 倍，且正确性论证只需一句双射。能在建模期消除的对称性，胜过在结果集上去重。
- **搜索规模由约束强度决定，而不是由候选空间大小决定。** 直接暴力 $1.34\times10^8$ 个候选，而「边互异」这一条约束把 DFS 的搜索树压到 $9\times10^4$ 个状态，相差三个数量级；$683$ ms 对 $0.5$ ms 的差距就是「按定义枚举」与「按结构枚举」的成本差。
- **独立复核要复核口径，而不是重复代码。** 方法 B 与 A 的 DFS 内核几乎相同，但把「首边固定 = 自动规范化」这一步换成了「自由首边 + 旋到全零边 + 集合去重」，正好守住了本题唯一容易理解错的题意（旋转口径）。
- **位运算的「位宽」是最易错的细节。** 暴力实现第一版把 $2^N$ 位的循环移位放在 32 位整数上做（`Integer.rotateLeft`），$N=3$ 时窗口立刻全错、答案变成 $0$；必须显式限制在 $2^N$ 位宽度内做旋转。模式类题目里，字长口径的错法与算法错误同样致命。
- **计数是最好的免费旁证。** 合法排列数 $2048$ 与 de Bruijn 序列计数闭式 $2^{2^{N-1}-N}$ 的吻合，独立于求和过程，等于给整套复杂度不高的枚举再加了一道结构性保险。
