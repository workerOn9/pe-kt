# 031 · 硬币组合 — 解析

## 思路推导

**把「凑法」翻译成计数问题**：问题等价于求不定方程

$$1x_1 + 2x_2 + 5x_3 + 10x_4 + 20x_5 + 50x_6 + 100x_7 + 200x_8 = 200,\qquad x_i \ge 0$$

的整数解个数。注意顺序无关——`1p + 2p` 与 `2p + 1p` 是同一种凑法——所以必须给「面额的使用」规定一个固定顺序，否则会数成排列数。

**完全背包计数**：设 $dp[i]$ 表示凑出金额 $i$ 的方案数，初始 $dp[0] = 1$（凑出 0 便士只有「什么都不取」这一种）。外层遍历硬币面额 $c$，内层让 $i$ 从 $c$ 递增到 200：

$$dp[i] \mathrel{+}= dp[i-c]$$

关键在于**外层是面额而不是金额**。这样每种面额只在自己的那一轮里被引入，任何方案唯一对应「先小面额、后大面额」的构造顺序，`1p+2p` 与 `2p+1p` 只会被计入一次。若把两层循环写反，同一种组合会在不同顺序下被反复累加，得到的是排列数。

**小规模自检**：把上限缩到 5 便士，可用面额只剩 1p、2p、5p，手工穷举恰有 4 种——`5`、`2+2+1`、`2+1+1+1`、`1×5`；同样的 DP 在这个小例子上的输出一致，可作为实现正确性的旁证。

答案：**73682**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：完全背包 DP | $O(8 \times 200)$ 次加法 | ~0.0011 ms |
| 暴力解：按面额降序递归枚举每个面额取几枚 | $O(\text{组合数})$，递归叶子恰为 73682 个，另有大量中间节点 | ~7.64 ms |

约 7000 倍差距来自两点：DP 每格只做一次加法，总共不到 1600 次运算；递归解法要为每一种取法走一遍完整路径，73682 个叶子意味着至少同样数量的函数调用与余额判断，且无法复用子问题的答案。这是「把重复子问题存起来」最直白的收益。

## 实现要点

- 初始条件 $dp[0]=1$ 是计数的关键：空组合本身就是一种方案，也是后续一切递推的种子
- **外层面额、内层金额**是组合计数的定式，写反就变成排列计数
- 内层从 `c` 开始递增而非从 0 开始，天然保证不会出现负下标
- 200 以内的方案数最大 73682，`Int` 足够；若面额或上限放大，应换成 `Long`
- 递归暴力版按面额降序枚举（200 先试），叶子数与组合数同阶，用于教学对比
