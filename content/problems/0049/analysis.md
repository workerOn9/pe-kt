# 049 · 素数排列 — 解析

## 思路推导

**先翻译题目的两个条件**。设三项为 $a < b < c$：

1. 等差：$b - a = c - b = d$，即 $c = 2b - a$，所以只需确定 $a$ 与 $b$；
2. 互为数字排列：三者的**十进制数位排序后完全相同**。

条件 2 给出了核心的规范化手段：对任意整数 $n$，把它的数字升序排列得到字符串

$$\operatorname{key}(n) = \text{sorted}(n)$$

它就是「数字多重集合」的指纹。$x$ 与 $y$ 互为排列 $\iff \operatorname{key}(x) = \operatorname{key}(y)$。

**分桶策略**：把 1000–9999 之间的所有素数按 $\operatorname{key}$ 分组。同一个桶里的任意两个数天然互为排列，跨桶的两数一定不是排列。于是「找三项互为排列的等差序列」就从「枚举全部素数对」缩小为「在每个桶内部两两配对」：

$$\text{桶内取 } a < b,\quad c = 2b - a,\quad \text{要求 } c \le 9999,\ c \text{ 是素数},\ \operatorname{key}(c) = \operatorname{key}(a).$$

由于 $c > b$ 且同桶，判定 $c$ 合法只需一次素性查表和一次字符串排序。

**去重与排除**：题目已经给出 $1487, 4817, 8147$ 这一组，要求的是「另一个」。实现中显式跳过拼接结果等于 `148748178147` 的那组，在全部候选中取最大值——四位数范围内满足条件的三元组只有这两组，另一组是

$$2969,\ 6299,\ 9629 \qquad (d = 3330),$$

答案：**296962999629**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：按数位指纹分桶，桶内配对 | 分桶 $O(\pi(10^4))$，桶内 $O(\sum m_i^2)$；$m_i$ 通常只有个位数 | ~0.19 ms |
| 暴力解：枚举所有四位数素数对 $(a,b)$，再判 $2b-a$ | $O(\pi(10^4)^2) \approx 5.6\times10^5$ 对，每次还要现场试除判素 | ~14.9 ms |

约 78 倍差距来自「排列等价类」这一层抽象。暴力解把绝大多数算力花在数字根本不是排列的数对上——例如 $(1009, 1013)$ 一眼就不可能是解；分桶把这种显然不可能的搭配从搜索空间里整片删除。这与数据库的哈希连接（hash join）如出一辙：先按连接键把两侧数据分组，再只在组内两两比较，避免笛卡尔积。

## 实现要点

- 数位指纹 `sortedDigits` 是排列判定的规范形式，比逐位比较更简洁也更不易出错
- 素性查表用 $10^4$ 的埃氏筛，$O(1)$ 查询；桶内需要反复判定 $c$，查表远比现场试除划算
- 桶内必须保证 $a < b$、$c = 2b - a > b$，否则会重复统计同一序列的不同书写顺序
- 显式排除题目给出的示例组，避免把已知答案当成新答案返回
- 四位数素数只有 1061 个，桶的规模很小，因此分桶的开销可以忽略
