# 思路推导

## 问题建模

设密钥为 $s_0 s_1 \dots s_{15}$，每条猜测定 义了「位置对齐的命中数」约束：
$$
\sum_{p=0}^{15} [g_p = s_p] = t.
$$
$10^{16}$ 全域枚举不可行，22 条约束互相耦合，逐位独立又不成立——需要**约束传播 + 回溯**。

## 约束传播回溯（CSP）

状态：
- 每个位置的候选数字集合（10-bit 掩码 `domains[p]`）；
- 每条 guess 的已入账命中数 `mc[gi]` 与「该位置是否已对这条 guess 入账」的标记 `assigned[p]`。

**赋值**：每轮用 MRV（Minimum Remaining Values）启发式选候选数最少的未定位，试放一个候选数字。

**传播**（入队去重，保证每条 guess 的命中数只入账一次，传播到不动点）：

1. **命中入账**：位置 $p$ 定为数字 $d$ 时，对每条 $g_{gi}[p] = d$ 的 guess 执行 $mc_{gi} \mathrel{+}= 1$；若 $mc_{gi} > t_{gi}$ 立即矛盾。
2. **上界传播**（$mc_{gi} = t_{gi}$ 已达目标）：其余每个未入账、未定死的位置 $q$ 必须取 $s_q \ne g_{gi}[q]$ 的数字——再命中就会超标。从候选集划掉 $g_{gi}[q]$。
3. **下界传播**（$mc_{gi} < t_{gi}$）：统计「未入账且候选仍包含 $g_{gi}[q]$」的位置数 $fm$：
   - $mc_{gi} + fm < t_{gi}$：命中数不可能凑够，剪枝；
   - $mc_{gi} + fm = t_{gi}$：**恰好够数**——所有这些位置必须全部钉死为 $g_{gi}[q]$，产生新的入账事件。
4. 新定死的位置重新入队，循环到稳定。

**叶子终验**：全部位置定死时逐条 guess 复核 $mc_{gi} = t_{gi}$（上界传播只保证 $\le$，必须显式排除「中途定死但从未被任何 guess 覆盖」的松散位）。

全树搜完（不找到第一个解就停），统计解个数——本 puzzle **恰为 1**，与题面「unique」声明一致。

## 关键实现细节

- 传播入队必须**去重**：同一位置被两次入队会让同一命中被 `mc` 计两次，过度剪枝后无解（实测踩过：0 解且跑满 3 分钟）。
- 回溯要**传值**（`copyOf` 后传参），不能用闭包共享可变数组，否则撤销状态错乱。
- 终检里 `Pair<Char, Char>` 上没有 `get`/`first()` 数组访问，直接比较 `it.first == it.second`。

## 旁证

- 5 位样例：Python 全枚举 $0..99999$ 与 Kotlin 同款算法都得到**唯一解 39542**，与题面一致。
- 最终串 `4640261571849533` 用 Python 逐条核验 22 条 guess 全部命中数精确吻合。
- 全树搜索证明解个数 $= 1$，无第二解。

## 答案

**4640261571849533**

## 复杂度对比

| 实现 | 复杂度 | 实测（JIT 预热后） |
|------|--------|--------------------|
| 全域枚举 $10^{16}$ | 不可行 | - |
| 朴素逐位回溯 | 分支巨大（实测 Python 7 分钟未出） | - |
| 约束传播 + MRV 回溯 | 搜索树约 $10^5$ 节点 | ~116 s（JVM，含全部解证明）|

## 教训

- Number Mind 是标准 CSP：值域剪枝（上界）+ 必要集剪枝（下界）都只消掉浅层分支，**「恰好够数 ⇒ 强制钉死」**的等式传播才是把搜索树压到可枚举的关键。
- 传播事件必须去重/幂等，否则正确性直接被破坏；这类 bug 的症状（无解、跑满时限）与「约束写错」完全一样，只能靠小样例对拍定位。
- 同一算法 Python 要 7 分钟以上，JVM 快约 4 倍；但相比模拟退火等启发式（无法证明唯一性），完整 CSP 证明才是本题要求的「unique」的正确打开方式。
