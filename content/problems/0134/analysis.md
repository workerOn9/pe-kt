# 134 · 素数对连接 — 解析

## 思路推导

**第一步：把「末位数字构成 $p_1$」翻译成同余。**

设 $p_1$ 有 $d$ 位十进制数字，记 $M = 10^d$。一个正整数末尾恰好是 $p_1$ 的这 $d$ 个数字，当且仅当它模 $M$ 的剩余等于 $p_1$。于是全部合格候选构成等差序列

$$
n = p_1 + k\cdot M,\qquad k = 0, 1, 2, \dots
$$

因为 $0 < p_1 < M$，这个写法唯一：$k$ 就是 $n$ 里 $p_1$ 之前那段前缀所表示的整数；反过来给定 $k$ 也唯一确定 $n$。$n$ 关于 $k$ 严格递增，所以「最小候选」等价于「最小 $k$」。

**第二步：加上整除条件，得到一元线性同余。**

要求 $p_2 \mid n$，即 $p_1 + kM \equiv 0 \pmod{p_2}$，整理得

$$
k\cdot 10^{d} \equiv -p_{1} \pmod{p_{2}} .
$$

本题范围内 $p_1 \ge 5$，而 $p_2 > p_1$，所以 $p_2 \ge 7$：它与 $10$ 互素，进而与 $10^d$ 互素，$10^d$ 在模 $p_2$ 下可逆。于是同余式在模 $p_2$ 意义下恰有一个解

$$
k \equiv -p_{1}\,(10^{d})^{-1} \pmod{p_{2}},
$$

取最小非负剩余 $k_0 \in [0, p_2)$ 即得

$$
S = p_1 + k_0\cdot 10^{d}.
$$

$k_0 = 0$ 不会发生：那要求 $p_2 \mid p_1$，与 $0 < p_1 < p_2$ 矛盾，因此恒有 $S > p_1$。

**第三步：逆元怎么算。** $p_2$ 是素数，费马小定理给出 $(10^d)^{-1} \equiv (10^d)^{p_2-2} \pmod{p_2}$，用平方-乘快速幂，$O(\log p_2)$ 次模乘。也可以改用扩展欧几里得求 $x, y$ 使 $10^d x + p_2 y = 1$；两者在这个规模下都是每对几十次基本运算，本解采用快速幂。

**为什么题面偏偏排除了 $(p_1, p_2) = (3, 5)$。** 对这对素数 $d = 1$、$10 \equiv 0 \pmod 5$，同余式左边恒为 $0$ 而右边 $\equiv 3$，无解——这正是「$\gcd(10^d, p_2) = 1$」这条前提唯一失效的地方。题面的例外说明并非随意，它是可逆性条件的边界。

**等价视角：中国剩余定理与「拼接」。** 两条约束 $n \equiv p_1 \pmod{10^d}$ 与 $n \equiv 0 \pmod{p_2}$ 的模数互素，故在模 $10^d p_2$ 下解唯一；又因该剩余 $\equiv p_1 \not\equiv 0$，它必是正的代表元，正是 $S$。用前缀-后缀的语言说：$S$ 就是把 $k_0$ 的十进制数字当作前缀、把 $p_1$ 的 $d$ 位数字当作后缀拼起来得到的整数。例如 $p_1 = 997147, p_2 = 997151$ 给出 $k_0 = 995751$，$S = 995751997147$。

**规模与取值范围。** $\pi(10^6) = 78498$，去掉 $2, 3$ 后共 **78496** 对相邻素数；筛的上界要开到 $10^6 + 20$，因为 $p_1 = 999983$ 的搭档是 $1000003$。$p_1 \le 10^6$ 时 $d \le 6$，于是单项

$$
n < p_2\cdot 10^{d} + p_1 < 1.01\times10^{12},
$$

实测最大的一项是 $995751997147$（出现在 $(997147, 997151)$）。总和 $1.86\times 10^{16} < 2^{63}-1 \approx 9.22\times10^{18}$，全程 `Long` 足够，不需要 `BigInteger`。

## 独立验证与答案

**定义式自检。** `solution.kt` 的 `checkByDefinition` 对每个样例用题目原文的三条性质复核，而不是只比对数值：$n$ 模 $10^d$ 的剩余等于 $p_1$（末位对）、$p_2 \mid n$（整除对）、且 $n - 10^d$ 不被 $p_2$ 整除（等差数列中它前面那项不合法，即最小性）。题面样例 $1219$ 三条全过。

**小规模逐值互证。** 前七对相邻素数的最小连接数由两条完全不同的路径给出同样的值：

| $(p_1, p_2)$ | $S$ | $(p_1, p_2)$ | $S$ |
|---|---|---|---|
| $(5, 7)$ | $35$ | $(17, 19)$ | $817$ |
| $(7, 11)$ | $77$ | $(19, 23)$ | $1219$ |
| $(11, 13)$ | $611$ | $(23, 29)$ | $2523$ |
| $(13, 17)$ | $1513$ | | |

其中 $1219$ 直接来自题面；其余六条由逐个试除手推，并与同余解一致。累加范围也做了端点检查：$p_1 = 19$ 的对要计入 $p_1 \le 19$，$p_1 = 17$ 时不计入。

**全规模的第二条路径。** [brute-force.kt](brute-force.kt) 完全不做解析求逆：从 $k = 0$ 起逐个试验 $n = p_1 + k\cdot 10^d$ 是否被 $p_2$ 整除，判整除用增量余数（每步 $r \mathrel{+}= 10^d \bmod p_2$，越界回减一次），循环体内没有乘除法，只有加法、减法与比较。它遍历的步数合计 $18817676144 \approx 1.88\times10^{10}$，平均每对 $239728$ 步，与优化解算出的 $\sum k_0$ 完全一致（同一批 $k_0$，一个靠解同余得到，一个靠一步一步走出来的）。两个文件独立打印出同一个结果，最终答案为 **18613426663617118**。

规模上的一处旁证：全部 $78496$ 对中 $d = 1,2,3,4,5,6$ 的对数分别是 $2, 21, 143, 1061, 8363, 68906$，最小值 $35$ 出现在第一对 $(5, 7)$，最大值 $995751997147$ 出现在 $(997147, 997151)$——两端的候选都能手算复核。

## 复杂度对比

设筛的上界 $N = 10^6$，素数对数 $P = \pi(N) - 2 = 78496$。

| 方案 | 时间 | 空间 | 实测（JIT 预热后） |
|---|---|---|---|
| 优化：埃氏筛 + 费马逆元（快速幂）解同余 | $O(N\log\log N + P\log N)$ | $O(N)$ | 8.4837 ms |
| 对照：埃氏筛 + 逐候选试除（增量余数） | $O(N\log\log N + \sum p_2)$，实测 $1.88\times10^{10}$ 步 | $O(N)$ | 9540.7088 ms |

优化解每对做一次 $O(\log p_2)$ 的模幂（$\le 20$ 次平方 + $\approx 10$ 次乘法），对照解每对平均要走 $239728$ 步纯加法。差距的**本质在步数而不在毫秒上**：优化解共做 $78496$ 次快速幂（约 $2.4\times10^6$ 次模乘），对照解共走 $1.88\times10^{10}$ 步，两者相差约 $4$ 个数量级；实测耗时相差 $1124.6$ 倍。优化的关键在于把「枚举 $p_2$ 个候选」换成「解一次线性同余」，把 $O(p_2)$ 压成 $O(\log p_2)$。

计时口径：两个解都在程序内 JIT 预热后自报耗时，由主 Agent 在空闲机器上各编译一次、独立进程重复 5 次取最小值；数字已同步进 `meta.json` 的两个 baseline 字段。

## 实现要点

- **筛的上界要留余量。** 循环条件按 $p_1 \le 10^6$ 筛选，但要为 $p_1 = 999983$ 取到下一个素数 $1000003$，筛到 $10^6$ 会数组越界或取错搭档。
- **位数用阈值比较，不要 `toString().length`。** 这是 025 留下的教训：把数值转成字符串再数位数，会白白分配大量临时对象。
- **互素前提要交代清楚。** 逆元存在的条件是 $\gcd(10^d, p_2) = 1$，即 $p_2 \ne 2, 5$；本题 $p_2 \ge 7$ 自动满足，而 $(3, 5)$ 正是这条前提失效的边界，代码与解析里都显式点出。
- **$k$ 必须归约到 $[0, p_2)$。** 直接写 `-p1 * inv % p2` 会得到非正数；加一次 $p_2$ 归约即可（`(p2 - (p1 % p2) * inv % p2) % p2` 中最后一次 `% p2` 处理了 $p_1 \equiv 0$ 的理论情形）。
- **乘法的溢出点只有两处**：$(p_1 \bmod p_2)\cdot \text{inv}$ 与 $k_0 \cdot 10^d$。前者的两个因子 $< p_2 \le 1000003$，乘积 $< 2^{40}$；后者 $< p_2 \cdot 10^6 < 2^{40}$。都在 `Long` 内，倒是暴力解里的余数增量用 `Int` 就够（$r + \text{step} < 2^{21}$）。
- **暴力解的步数是可预测的。** 因为 $k_0$ 只依赖 $p_1, p_2$，朴素解的总步数恰为 $\sum k_0 = 18817676144$；这也是判断「暴力能不能在可接受时间内跑完」的依据。
