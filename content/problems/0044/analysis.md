# 044 · 五边形数 — 解析

## 思路推导

**核心难点不是枚举，而是「判定一个数是不是五边形数」要足够快。** 最笨的办法是不断生成 $P_1, P_2, \dots$ 直到超过目标值，代价 $O(\sqrt{n})$；把它换成常数时间，整个搜索才可行。

从 $P_n = n(3n-1)/2$ 出发反解：

$$24P_n + 1 = 36n^2 - 12n + 1 = (6n-1)^2 .$$

因此 $x$ 是五边形数，**当且仅当** $24x+1$ 是完全平方数，且其平方根 $s$ 满足 $s \equiv 5 \pmod 6$（此时 $n = (s+1)/6$）。整数开方（浮点开方加邻域校正）是 $O(1)$ 操作，判定问题就此解决。

**枚举策略**：按 $k$ 递增枚举 $P_k$，对每个 $k$ 让 $j$ 从 $k-1$ 递减到 1，检查

$$P_k - P_j \quad\text{与}\quad P_k + P_j$$

是否都满足上面的判别式，第一个全部通过的 $D = P_k - P_j$ 即为答案。让 $j$ 递减是为了尽快撞上较小的差值（差值随 $j$ 减小而增大，但本题的解出现在 $j$ 相对较大处，实测在 $k=2167,\ j=1020$ 命中）。

**结果核对**：$P_{1020} = 1560090$，$P_{2167} = 7042750$，二者之差 $5482660$，之和 $8602840 = P_{2395}$——和、差确实都是五边形数。题目只要求给出 $D$，但把数对一并列出能验证实现没有误解题意。

答案：**5482660**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：判别式 $O(1)$ 判定 + 边枚举边配对 | $O(k^2)$ 次数对比较，每次为常数时间整数运算 | ~10.5 ms |
| 暴力解：先预生成 3000 个五边形数并存入 `HashSet` 再双重循环 | 同为 $O(k^2)$，但每次配对要做两次哈希查找 | ~45.1 ms |

两者的渐进复杂度相同，差距来自常数因子：暴力解把五边形数装进装箱 `Long` 的哈希集合，每次查询要计算哈希、处理装箱对象；优化解直接用整数开方判定成员资格，不物化任何容器。这是「换一个判定方式，而不是换一个算法」也能拿到数倍加速的典型例子——所以在做性能对比时，先问清楚绕不开的真实工作量是什么。

## 实现要点

- 判别式 $24x+1=(6n-1)^2$ 是本题全部加速的来源，务必先推出来再写循环
- 整数开方用 `Math.sqrt` 得到近似值后，在邻域内（$\pm 1$ 或 $\pm 2$）校正，规避浮点误差
- 仅检查 $s^2 = 24x+1$ 还不够，必须加上 $s \equiv 5 \pmod 6$，否则会误判（例如 $x=1$ 之外的非五边形数）
- 内层 $j$ 从 $k-1$ 递减、命中即返回，无需遍历全部数对
- 结果可能超出 `Int`，全程用 `Long`
