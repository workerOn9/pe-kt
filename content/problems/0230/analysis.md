# 230 — Fibonacci Words（斐波那契词）

## 思路：把 $10^{17}$ 位字符串的随机访问变成 $O(\log n)$ 递降

$|T_k|$ 按斐波那契数列增长：$L_0 = L_1 = 100$，$L_k = L_{k-1} + L_{k-2}$。要访问的最大下标是

$$
(127 + 19\cdot 17)\cdot 7^{17} = 104683731294243150 \approx 1.05\times 10^{17},
$$

而 $L_{73} = 130496954492865700$ 才刚覆盖它 —— 整串有 $1.3\times 10^{17}$ 位，**根本建不出来**。所以必须只存长度表。

递归定义 $T_k = T_{k-1} + T_{k-2}$ 展开后的字符串，就是「前 $L_{k-1}$ 位来自 $T_{k-1}$，剩下的来自 $T_{k-2}$」的经典自指结构。于是：

```
digit(n):
  k ← 最小的满足 L[k] ≥ n 的下标
  while k > 1:
      if n ≤ L[k-1]:  k ← k-1          # 落在左半，落进 T[k-1]
      else:           n ← n - L[k-1]; k ← k-2   # 落在右半，落进 T[k-2]
  return (k == 0 ? A : B)[n-1]
```

每步 $k$ 至少减 1，最多 73 步，与字符串长度完全无关。

## 拼接顺序：本题的真正坑

题面写的是 $(A, B, AB, BAB, ABBAB, \dots)$，即**第 3 项 = 第 1 项 + 第 2 项**：

$$
T_2 = AB,\quad T_3 = BAB = BA + B = T_1 + T_2,\quad T_4 = ABBAB = T_2 + T_3.
$$

也就是 $T_k = T_{k-2} + T_{k-1}$（$k \ge 2$），**不是**常见的 $T_{k-1} + T_{k-2}$。写反了递降公式会给出 $D(35) = 8$，与题面示例的 9 矛盾。

## 旁证

1. **复现题面示例**：取 $A = 1415926535$、$B = 8979323846$，按 $T_k = T_{k-2} + T_{k-1}$ 展开，前五项为
   $1415926535 \to 8979323846 \to 14159265358979323846 \to 897932384614159265358979323846 \to 14159265358979323846\cdots$，
   第 5 项第 35 位确为 **9**，与题面完全一致。
2. **显式对拍**：把词显式拼到 $7.5\times 10^6$ 位，对 $1, 2, 35, 100, 101, 200, 999, 5000, 25000, 100000, 1000000$
   共 11 个下标逐一比对，**零差异**。

## 答案

各位数字（从 $10^0$ 位到 $10^{17}$ 位，即 $n = 0, 1, \dots, 17$ 顺序）：

$$
6,\ 9,\ 2,\ 9,\ 1,\ 1,\ 3,\ 9,\ 5,\ 2,\ 5,\ 1,\ 1,\ 8,\ 4,\ 0,\ 5,\ 8
$$

$$
\boxed{850481152593119296}
$$

## 复杂度对比

| 方法 | 复杂度 | 实测 |
|------|--------|------|
| 暴力：显式拼串到 $10^6$ 位再取字符 | $O(10^6)$ 内存 + 时间 | 约 1 ms，但**只能覆盖前 $10^6$ 位** |
| 暴力：显式拼到最大下标 | $O(1.3\times 10^{17})$ 内存 | **不可行** |
| 长度表 + 自顶向下递降 | $O(\log n_{\max})$ ≈ 73 步 × 18 次 | < 1 ms |

## 关键教训

- **压缩表示 + 长度表 = 巨大字符串的随机访问**。只要结构是自指的（前缀 + 递归），就能只记 $O(\log n)$ 个长度而在 $O(\log n)$ 内定位任意字符。斐波那契词、Zimin 词、Thue–Morse 序列都是这个套路。
- **递降时先判左半再改下标**，顺序写反是这类题最常见的错误来源；而题面给出的示例正是唯一的正确性锚点 —— 拿到示例先跑一遍比读十遍定义都有用。
- **$7^{17}$ 与 $10^{17}$ 级别的下标要用 64 位整型**。$\sum 10^n D$ 的答案 $8.5\times 10^{17}$ 也在 Long 范围内（< 9.22×10^18），无需 BigInteger。
- **按 $10^n$ 加权 ⇒ 低位在前**，调试时先打印各位数字再打印总和，能立刻看出是「某一位错」还是「整体偏移」。
