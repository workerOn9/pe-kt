# 042 · 编码三角数 — 解析

## 思路推导

单词值只是字母序号的求和，真正的判定对象是：给定 $v$，是否存在正整数 $n$ 使

$$v = t_n = \frac{n(n+1)}{2}$$

把右边展开成关于 $n$ 的二次方程：

$$n^2 + n - 2v = 0$$

求根公式给出 $n = \dfrac{-1 + \sqrt{1 + 8v}}{2}$（舍去负根）。$n$ 是正整数，当且仅当**判别式 $1 + 8v$ 是完全平方数，且其平方根为奇数**。奇数条件实际可以省掉：$1 + 8v$ 恒为奇数，它的平方根若是整数必为奇数。因此判定简化为一步：**$8v + 1$ 是否为完全平方数**。

以 SKY 验证：$v = 19 + 11 + 25 = 55$，$8v + 1 = 441 = 21^2$，$n = (21 - 1)/2 = 10$，确实 $t_{10} = 55$。

之后就是工程问题：读入 `words.txt`，按逗号切分、去掉引号，逐词求值判定。单词最长 14 个字母，单词值上界 $26 \times 14 = 364$，对应的 $n \le 26$，数据规模微不足道；瓶颈在文件 IO 本身。

答案：**162**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：$8v+1$ 完全平方判定 | $O(L)$，$L$ 为文件字符数 | ~0.110 ms |
| 暴力解：预生成前 100 个三角数查表 | $O(L)$，同阶 | ~0.115 ms |

两者渐近复杂度相同，差距仅约 5%：暴力解多付一次哈希集合的构建与查找开销，而优化解每个单词只做一次开方加一次平方校验。这种「判别式开方判定」相对「预生成查表」的优势，在值域更大、判定更频繁时会真正体现出来（查表需要 $O(\max v)$ 的预生成内存）。

## 实现要点

- 单词值用 `w.sumOf { it - 'A' + 1 }` 一行求出，依赖输入全是大写字母
- 完全平方判定用 `Math.sqrt` 取整后在 $\pm 1$ 邻域内回验平方，规避浮点误差（$8v+1 \le 2913$，双精度绰绰有余，回验只是稳妥习惯）
- 奇根条件 $k \bmod 2 = 1$ 显式保留，与推导一一对应
- 文件解析：`split(',')` 后 `trim('"')` 去引号，`filter { isNotEmpty() }` 容错空词
