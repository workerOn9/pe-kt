# 034 · 各位数字的阶乘 — 解析

## 思路推导

**暴力枚举的上界必须先定死。** 假设候选数 $n$ 有 $d$ 位，则各位数字的阶乘之和最大为 $d \times 9! = 725760 \cdot d$（每位都取 9）。而当 $d = 8$ 时，最小的 8 位数是 $10^7$，已经超过了和的理论上限 $8 \times 9! = 2903040$。所以候选数最多 7 位，扫描范围取 $3 \le n \le 7 \times 9! = 2540160$ 即可全覆盖——超过此界的数，其阶乘和永远追不上自身。

**判定逻辑**：预存 $0..9$ 的阶乘表（$0! = 1! = 1$，别漏了 0 会进位位），对每个候选数逐位取余累加 $f[x \bmod 10]$，与原数相等即为命中。从 3 开始扫描，因为 $1! = 1$、$2! = 2$ 是「自身」而非「和」，题面明确排除。

**数学旁证（命中数只有有限个，且能缩小搜索）**：阶乘和只依赖数字的多重集合，与排列无关。一个更强的观察是 $9! = 362880$ 占 $d \times 9!$ 的绝大部分，位数每多一位，数本身要乘 10，而和只多 $9!$——这就是「位数越多越不可能相等」的根本原因，也解释了为什么答案只有 $145$ 与 $40585$ 两个数（$40585 = 4! + 0! + 5! + 8! + 5! = 24 + 1 + 120 + 40320 + 120$）。实测枚举全范围内命中恰好这两个，和为 $145 + 40585$。

答案：**40730**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：预存阶乘表 + 逐位取余累加 | $O(N \log_{10} N)$，$N = 7 \times 9!$ | ~29.2 ms |
| 暴力解：转字符串 + 逐位递归重算阶乘 | 同阶，常数大数倍 | ~190.9 ms |

约 6.5 倍差距来自两处常数因子：暴力解每个数都要做字符串分配与字符解码，且每位数字的阶乘都重新递归计算一遍（子问题毫无复用）；优化解用查表 $O(1)$ 取代重复阶乘，并用取余/除法直接拆位，避免了对象分配。两者扫描范围相同，差异纯粹是内循环的贵贱。

## 实现要点

- 上界 $7 \times 9! = 2540160$ 由「8 位数最小值 $10^7 > 8 \times 9!$」推出，先证后扫
- 阶乘表包含 $0! = 1$（含 0 的数如 40585 依赖它），用 `IntArray(10)` 一次预存
- 拆位用 `x % 10` / `x /= 10`，**不转字符串**（与 025 的教训一致）
- 从 3 起扫，跳过 $1! = 1$、$2! = 2$ 这两个退化情形
- 命中数仅 145、40585 两个，可用作单测断言 sanity check
