# 036 · 双进制回文数 — 解析

## 思路推导

**回文判定的成本很低，本题的全部优化都在「少检查一半候选」上。**

关键观察：二进制下的回文数（除 1 外）必为奇数。二进制表示的首位永远是 1，若末位是 0 则该数能被 2 整除；而回文要求首尾对称——末位为 0 意味着首位也应为 0，即出现了前导零，被题面明令禁止。因此**大于 1 的二进制回文数末位必为 1，即必为奇数**。小于一百万的候选从 999999 个直接砍掉一半。

**筛选顺序**：十进制回文判定作为前置过滤器（约 1/10 的整数是十进制回文，奇数中约 1/10 通过），命中后才做二进制回文判定，两个判定都是 $O(\text{位数})$ 的字符串比较。实测全表仅 19 个数通过双重过滤：

| 满足条件的数（共 19 个） |
|---|
| 1, 3, 5, 7, 9, 33, 99, 313, 585, 717 |
| 7447, 9009, 15351, 32223, 39993, 53235 |
| 53835, 73737, 585585 |

穷举可证完备：小于 $10^6$ 的奇数中十进制回文恰为 1110 个（1 位 5 个、2 位 5 个、3 位 50 个、4 位 50 个、5 位 500 个、6 位 500 个，首位必须为奇数），逐一验证二进制回文后恰剩上表 19 个。由于题面样例 $585 = 1001001001_2$ 确为双回文，方向无误。

求和：

$$1 + 3 + 5 + \cdots + 73737 + 585585 = 872187$$

答案：**872187**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：仅遍历奇数 + 内置 `toBinaryString` | $O(N \log N)$（$N = 10^6$） | ~14.8 ms |
| 暴力解：遍历全部整数 + 手工除 2 构造二进制串 | $O(N \log N)$，常数约 2 倍 | ~25.0 ms |

两者渐进复杂度相同，差距来自常数因子：候选数减半（奇偶剪枝砍掉一半无效迭代），且二进制串用 JDK 内置 `Integer.toBinaryString` 生成，比手动 `% 2` / `/= 2` 循环追加 `StringBuilder` 快。本题规模下 1.7 倍差距是「剪枝 + 用对内置函数」的典型收益，不涉及算法阶的跃迁。

## 实现要点

- 奇偶剪枝是本题唯一实质优化：二进制回文 > 1 必为奇数，数学上严格成立而非启发式
- 十进制回文判定先行（命中率约 10%），避免为每个候选构造二进制串
- 回文判定用「字符串与其反转相等」，比双指针慢但代码最短；$10^6$ 规模下差距可忽略
- 暴力版手工构造二进制串时用 `while (x > 0) { append(x % 2); x /= 2 }`，注意直接追加余数所得串本身就是低位在前，无需再反转
