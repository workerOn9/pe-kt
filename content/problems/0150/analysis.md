# 150 · 子三角形求和 — 解析

## 思路推导

**先把对象写清楚。** 行从 0 起编号，第 $r$ 行有 $r+1$ 个元素，记作 $a(r,c)$（$0 \le c \le r$），题面下标 $k = r(r+1)/2 + c + 1$ 对应 $s_k$。顶点 $(r,c)$、高 $h$ 的子三角形是

$$
\{(r+i,\ c+j)\ :\ 0 \le j \le i \le h-1\},
$$

共 $h(h+1)/2$ 个元素：第 $r+i$ 行取的是列 $c \dots c+i$。候选总数（每个顶点取遍 $1 \le h \le n-r$）为

$$
\sum_{r=0}^{n-1}(r+1)(n-r) = \frac{n(n+1)(n+2)}{6} = 167\,167\,000 \quad (n = 1000).
$$

**朴素做法不可行。** 按定义对每个三角形逐元素求和是 $\sum_{\text{三角形}} h^2/2 = O(n^5) \approx 8\times 10^{12}$ 次加法；就算用行前缀让每层的行段和变成 $O(1)$，只要高度维度不复用，仍有 $\sum_{\text{三角形}} h \approx n^4/24 \approx 4.2\times 10^{10}$ 次查表。所以必须在「同一顶点不同高度」之间建立递推。

**关键递推：沿对角线把三角形劈成两半。** 把 $(r,c,h)$ 拆成 $j = i$ 与 $j < i$ 两部分：

- 对角线部分 $D(r,c,h) = \sum_{i=0}^{h-1} a(r+i,\,c+i)$；
- 其余部分 $\{(r+i,c+j) : j < i \le h-1\}$。作替换 $i' = i-1,\ j' = j$，条件化为 $0 \le j' \le i' \le h-2$，行号变成 $r+1+i'$——这恰好是「顶点 $(r+1,c)$、高 $h-1$」的子三角形。

于是得到核心递推

$$
T(r,c,h) = T(r+1,c,h-1) + D(r,c,h),
\qquad
D(r,c,h) = D(r,c,h-1) + a(r+h-1,\ c+h-1).
$$

**层间传递的必须是对角线。** 一个常见的错误写法是「$T(r,c,h) = T(r+1,c,h-1)$ 加上第 $r$ 行的那一段」。注意两处的行索引含义不同：父三角形在行 $r+1+u$ 上取列 $c \dots c+u+1$，而子三角形在同一行上只取列 $c \dots c+u$，每层都少最右边那个元素。少掉的部分连起来正是对角线 $c+i$，必须单独补上；照错误写法在示例上会算出 $1$ 而不是 $-42$。

**分层 DP。** 自底向上处理行 $r = n-1, \dots, 0$：处理第 $r$ 行时，第 $r+1$ 行全部顶点的「按高度向量」$T(r+1,c,\cdot)$ 还在缓冲里，于是每个状态只需两次加法：一次把对角线累加一位，一次接上下一行同列顶点的高 $h-1$。第 $r$ 行的层规模是 $(r+1)(n-r)$ 个 `Long`，在 $r \approx n/2$ 处取到最大值 $250500$，两块缓冲交替复用即可，不必存满三维表。

**布局。** 每个顶点的 $D$ 累加走过的都是「行列差 $r-c$ 恒定」的右斜对角线。把原数组按对角线连续存放（对角线 $dd$ 的第 $p$ 项就是元素 $(dd+p,\,p)$，起始下标 $dd\cdot n - dd(dd-1)/2$），累加就退化成顺序读内存；层缓冲本身也是顺序读写。三处访存全部连续，这是后面常数差距的主要来源。

## 独立验证与答案

- **题面文本给的随机数**：两支实现都断言 $s_1 = 273519$、$s_2 = -153582$、$s_3 = 450905$，总数 $500500 = 1000\cdot1001/2$，取值全部落在 $\pm 2^{19}$ 内。
- **题面图示的六行示例**：英文题面这里给的是图片，把图示六行重排成文字后（顶点 $(1,1)$、高 $4$ 的三角形），逐元素定义式与两支实现都给出 $-42$，与题面标注的数值一致——这也反证了文字重排没有抄错。
- **小规模双方法互证**：$n = 64$ 时，$O(n^5)$ 的逐元素定义式与分层 DP 结果完全相同；两支实现也都对 $n=64$ 做了同样的比对。
- **两条独立路径**：`solution.kt` 用「对角线分解 + 跨顶点分层 DP + 对角线连续布局」；`brute-force.kt` 用「同一顶点内加行 + 行前缀求段和、顶点之间零复用」。两者思路与数据结构都不同，$n = 1000$ 上都输出同一个值。

最小子三角形和是 **-271248680**。

## 复杂度对比

| 方案 | 时间 | 空间 | 实测（JIT 预热后） |
|---|---|---|---|
| 优化：分层 DP，对角线分解，对角线连续布局 | $O(n^3)$（精确 $n(n+1)(n+2)/6 = 1.67167\times 10^8$ 次迭代，每次 2 次加法） | $O(n^2)$（原数组 + 两块层缓冲，最大一层 250500 个 `Long`） | 150.0586 ms |
| 对照：逐顶点加行，行前缀求段和，顶点间零复用 | 同为 $O(n^3)$ 次迭代，但每次 2 次跳跃查表 + 1 次减法，两次读取都落在前缀数组的斜向/竖直位置 | $O(n^2)$（行前缀数组，无层缓冲） | 266.3857 ms |

两支实现都要访问全部 $167167000$ 个候选三角形，差距只来自每次迭代的算术量与访存模式：优化解三处访存连续、每步 2 次加法；对照解每步 2 次跨行查表（读取方向是斜线与竖直，步长为行长），cache 命中率明显更低。按最小值算约 $266.3857/150.0586 \approx 1.8$ 倍。

计时口径：两个解都在程序内 JIT 预热后自报耗时，由主 Agent 在空闲机器上各编译一次、独立进程重复 5 次取最小值；数字已同步进 `meta.json` 的两个 baseline 字段。

**这一对比说明的是常数与访存布局，不是量级差异**：两个解同为 $O(n^3)$（都恰好枚举 $167167000$ 个候选三角形、每个常数时间），观测到的倍速在 $1.8$ 倍上下，属于常数因子的差别。

## 实现要点

- **递推里层间传递的是对角线，不是行段**。父三角形每行比子三角形多最右边一个元素，这些元素连成对角线；漏掉它们会得到偏大的答案（示例上给出 $1$ 而不是 $-42$）。
- **必须用 `Long`**。单元素只在 $\pm 2^{19}$ 内，但整个三角数组的和可达 $500500 \times 2^{19} \approx 2.6\times10^{11}$，中间量用 `Int` 会静默溢出；同时最小值可能是负数，`best` 不能初始化为 $0$。
- **层缓冲大小按 $(r+1)(n-r)$ 估**，最大值在 $r \approx n/2$，为 $250500$，两块缓冲互换即可，省下整张三维表。
- **对角线布局的下标**：对角线 $dd = r-c$ 从 $dd \cdot n - dd(dd-1)/2$ 开始，长度 $n-dd$；顶点 $(r,c)$ 的扫描从该对角线第 $c$ 项起走 $n-r$ 步，步数正好等于它的高度上限。
- **样例断言只能加严**：题面没有给出英文题面里那张图的数字文本，本实现把图示六行重排为文字并断言最小和 $-42$，同时用 $O(n^5)$ 定义式在 $n=64$ 上做无依赖的交叉验证。
