# 035 · 循环素数 — 解析

## 思路推导

**暴力思路**：筛出 $10^6$ 以内所有素数，对每个素数把它的十进制表示循环移位，逐一查表确认每个旋转都是素数。十亿以下规模这完全可以跑，但没有用到任何结构。

**关键剪枝（数位预筛）**：若一个多位循环素数 $n$ 的某一位是偶数或 $5$，则必然存在某个旋转把这一位挪到末位——末位为偶数或 $5$ 的数必为合数（末位偶数是 $2$ 的倍数，末位 $5$ 是 $5$ 的倍数），矛盾。因此**多位循环素数的每位数字只能取自 $\{1, 3, 7, 9\}$**。百万以内只剩 $4 + 4^2 + 4^3 + 4^4 + 4^5 + 4^6 = 5460$ 个候选（含一位特例 $2, 3, 5, 7$），相对全部 $78\,498$ 个素数是 $7\%$ 不到的候选量。

在这个候选集上做旋转判定即可。旋转数的素性判定只需查筛法表，每题旋转次数为位数 $-1$，总开销约 $5460 \times 5 \approx 2.7$ 万次查表。

按位数统计最终结果为：一位 $4$ 个（$2,3,5,7$）、两位 $4$ 个、三位 $8$ 个、四位 $10$ 个、五位 $14$ 个、六位 $11$ 个，合计 $55$ 个。

答案：**55**。

## 复杂度对比

| 方案 | 时间 | 实测（JIT 预热后） |
|------|------|------|
| 优化解：筛法 + 数位预筛 $\{1,3,7,9\}$ 后再旋转判定 | $O(N \log\log N) + O(D \cdot d)$ | ~10.73 ms |
| 暴力解：筛法 + 对每个素数全量旋转判定 | $O(N \log\log N) + O(\pi(N) \cdot d)$ | ~14.29 ms |

两版的主要开销都是埃氏筛本身（百万级筛法约 $10$ ms 量级），差距来自**旋转判定的候选量**：暴力版对全部 $78\,498$ 个素数做字符串旋转与查表，优化版先用数位条件把候选砍到 $5460$ 个，旋转判定次数约为原来的 $1/14$。这 $1.3$ 倍的端到端差距说明：当筛法占大头时，剪枝的收益被摊薄——但它仍把热点从「字符串操作」转移到了可以忽略的查表。

## 实现要点

- 筛法用 `BooleanArray` 标记合数，一次筛到 $10^6$，素性判定 $O(1)$ 查表
- 数位预筛：`s.any { (it - '0') % 2 == 0 || it == '5' }`，一行排除 $90\%$ 以上候选
- 旋转用 `substring(i) + substring(0, i)` 生成，转回整数查表；单位数天然满足条件
- 剪枝依据依赖**每位**都安全（而非仅末位），别把条件放宽成只查末位
